# Android Back: regression suite

**Текущее состояние: GREEN.** Два последовательных полных прохода на Android
API 36: по **23 PASS, 0 FAIL, 0 ERROR**. Все 10 исходных нарушений исправлены
в проверенных сценариях. Первый Back скрывает IME и сохраняет экран/текст,
следующий выполняет ожидаемую навигацию.

Проверки перенесены по `D:/Projects/TaskRadar/docs/android-back-testing-guide.md`.
Сначала проверки зафиксировали нарушения на стадии RED TDD. После исправления
они проверяют порядок «клавиатура → навигация». Suite проверяет правила 1 и 8
гайда, а не вводит весь
его контракт подтверждения несохранённых изменений в CashFlow.

## Запуск

### Что запускается автоматически

| Проверка | Автоматически | Где запускается |
| --- | --- | --- |
| Flutter widget-регрессии Back, включая `keyboard_first_back_test.dart` и MCC | Да, после публикации изменений | `.github/workflows/frontend-ci.yml`: общий `flutter test`; вызывается CI для push/PR в dev/main и проверками release workflow |
| Все 23 сценария с настоящей Android IME и `KEYCODE_BACK` | Нет | Локально через `scripts/test-android-back.ps1` на подготовленном эмуляторе |

Сборка подписанного APK в release workflow **не запускает** эмуляторную
Back-suite. Зелёный `Frontend CI` подтверждает widget-тесты, но сам по себе
не доказывает порядок закрытия настоящей Android-клавиатуры. Эмуляторный
runner автоматизирует действия и проверки после ручного запуска команды;
GitHub Actions, расписание и обязательный CI-gate для него пока не настроены.
Два локальных полных прохода №6 и №7 ниже относятся к исправлению в этом релизе.

### Команды и подготовка

```powershell
.\scripts\test-android-back.ps1 -Device emulator-5554
.\scripts\test-android-back.ps1 -Passes 2
.\scripts\test-android-back.ps1 -SkipBuild -Passes 2
.\scripts\test-android-back.ps1 -SkipBuild -Only 'benefit / MCC'
.\scripts\test-android-back.ps1 -SkipBuild -FirstPass 2 -Only ' / search'
```

Нужны Node.js 20+, adb, aapt, запущенный отдельный телефонный AVD и настроенный
в VS Code Flutter SDK. npm-пакеты не нужны. Сборка release с debug-подписью
использует существующий `CASHFLOW_OFFLINE_QA_METRICS=true`, пакет
`com.example.cash_app.offlineqa` и API `http://10.0.2.2:18742`.
APK проверяется через aapt перед установкой. `-SkipBuild` использует только
сохранённый `results/cashflow-backqa.apk`.

Runner очищает только QA-пакет на эмуляторе, входит через настоящую форму
под синтетическим администратором и перезапускает процесс перед каждым
сценарием. Production, обычный пакет и пользовательские данные не используются.
API слушает только loopback, возвращает 404 на неизвестные маршруты и не
записывает тела запросов/токены. Любой запрос изменения данных, кроме входа,
считается ошибкой. Сервер и настройка handwriting восстанавливаются в finally.

## Проверяемый контракт

| Шаг | Обязательное наблюдение |
| --- | --- |
| Открыть экран | Уникальный заголовок/идентификатор доступен |
| Нажать поле | `dumpsys input_method`: `mInputShown=true`, EditText имеет фокус |
| Ввести ASCII-маркер | Значение присутствует в EditText; исходный экран подтверждён ещё раз |
| Первое Back | `mInputShown=false`, тот же экран/детальное представление и точное значение поля |
| Второе Back тем же способом, где указан parent | Показан ожидаемый родитель, клавиатура скрыта |

Hardware — настоящий `adb shell input keyevent KEYCODE_BACK`, app-bar — нажатие
на доступную кнопку `Back` в заголовке. Это отдельные тестовые строки.
Widget `handlePopRoute()` не используется как имитация системной IME.
Нажатия выполняются по семантическим идентификаторам/подписям без фиксированных
координат. Для трёх безымянных кнопок редактирования добавлены только
`Semantics(container: true, identifier: 'edit-user-…')` (и аналогичные bank/card)
в приложение; поведение этих кнопок редактирования не менялось. `container` удерживает идентификатор
на самой кнопке, а не на объединённой строке списка.

**Точное воспроизведение обратного порядка:** Выгода → нажать поиск → набрать
`5411` → дождаться MCC-результата, не закрывая клавиатуру → KEYCODE_BACK.
Запрос очищается и результат закрывается, при этом `mInputShown=true` даже
после ожидания. Дополнительный KEYCODE_BACK скрывает клавиатуру
(`afterSecondBack.imeHidden=true`). В ожидаемом поведении первое нажатие
должно сохранить `5411` и MCC-результат и только скрыть клавиатуру.

**Стрелки:** первое нажатие закрывает страницу/редактор и теряет введённое
значение вместо того, чтобы остаться на странице и скрыть только IME.
В большинстве этих случаев к моменту чтения дерева клавиатура уже скрылась
вместе с уходом с маршрута; нарушение доказывается именно преждевременным
уходом и потерей поля, а не утверждением о покадровом порядке анимаций.

### Формат отчёта

`results/back-pass-N.json` (игнорируется Git) содержит время UTC, API level,
IME, verdict и шаги каждой строки, дерево до/после, наличие клавиатуры,
сохранение экрана и точного текста. Все три условия фиксируются до проверки,
поэтому видно различие между уходом со страницы и потерей текста.
Если hardware Back оставил клавиатуру открытой, после уже зафиксированного
FAIL отправляется дополнительный Back для диагностики обратного порядка;
это не повтор теста и не превращает FAIL в PASS.

`failed` означает нарушение контракта приложения; `error` — не удалось
подготовить/наблюдать сценарий. Процесс завершается ненулевым кодом в обоих
случаях. Ожидание доступности дерева не повторяет нажатие Back. Сценарии не
перезапускаются для получения зелёного результата.

Эта матрица не является полным аудитом всех полей: не покрыты форма входа,
редактирование MCC-ревизий, импорт, все поля редактора категории, платежи
подписки, широкие layouts и жест predictive back. Проверены KEYCODE_BACK и
стрелки на Android Emulator; физическое устройство и production не проверялись.
Для приёмки исправления нужны два последовательных полных прохода без
failures, errors или повторных попыток.

## Исправление

`app/lib/screens/widgets/keyboard_first_back.dart` содержит общую проверку
видимой клавиатуры по `FlutterView.viewInsets.bottom`. Один лишь фокус поля
не означает открытую IME: Android может оставить фокус после её закрытия.
При видимой IME обработчик снимает фокус и завершает Back без навигации.

Шесть экранов со стрелками используют `KeyboardFirstBackButton`: Карты и
категории, пользователь, эмодзи, банк, карта и редактор подписки. После
закрытия клавиатуры стрелка вызывает `Navigator.maybePop`, сохраняя работу
возможных PopScope-защит. Та же проверка стоит перед изменением состояния
в PopScope «Выгоды» и оболочки вкладок: первый Back не очищает MCC-запрос
и не меняет историю вкладок.

Эмуляторная проверка усилена: после скрытия IME второе нажатие той же стрелки
обязано вернуть родителя; для MCC второй системный Back должен закрыть
MCC-результат и очистить запрос. Исходные проверки сохранения экрана и текста
на первом нажатии сохранены.

Flutter-регрессии `keyboard_first_back_test.dart` и `mcc_search_test.dart`
проверяют сохранение маршрута/текста при видимой IME, последующую навигацию,
уважение PopScope и сохранение MCC-результата. Выбранные четыре test-файла:
30 PASS. Статический анализ изменённых файлов: без замечаний.
Перед запуском релиза 17.10.2026 дополнительно выполнены полный
`flutter analyze` (без замечаний) и весь `flutter test`: **187 PASS**.
