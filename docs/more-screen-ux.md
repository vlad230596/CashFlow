# Экран «Ещё»

Статус: утверждено и реализовано во Flutter 22 сентября 2026 года на существующих контрактах.

## Назначение

«Ещё» — служебный хаб для редких действий, которые не должны конкурировать с повседневными сценариями «Выгоды», «Плана» и «Акций». Экран собирает уже существующие возможности приложения: обновление данных, Windows-импорт кешбэка, управление банками, картами и владельцами, правила MCC, выбор расчётной даты, сведения о сеансе и выход.

Экран не является личным кабинетом и не обещает полноценное семейное пространство. В текущей модели `UserModel` — владелец карты с `id` и `name`, а авторизованный пользователь (`AuthIdentity`) — отдельная сущность с ролью. Приглашений, нескольких семей, семейных ролей и переключателя пространства в коде нет.

## Основание в текущем продукте

| Блок | Фактическая возможность | Доступность |
| --- | --- | --- |
| Обновить данные | `DataProvider.fetchAllData()`; при ошибке остаются локально сохранённые данные | все авторизованные пользователи |
| Импортировать JSON | выбор файла и `importCashbackDocument()` | только Windows; действие редактирования требует `editor` или `admin` |
| Запросить кешбэк | запуск локального Chrome-сценария с одним из двух профилей | только локальное Windows-приложение |
| Банки | список, создание, редактирование и удаление | только `admin` |
| Карты | список, создание, редактирование и удаление | только `admin` |
| Владельцы карт | список, создание, редактирование и удаление | только `admin` |
| Правила MCC | ревизии по банку, ручной снимок, публикация; автоматический импорт сейчас является серверной заглушкой | только `admin` |
| Расчётная дата | выбрать дату кешбэка или вернуться к сегодняшней | все авторизованные пользователи |
| Сеанс | логин, роль и адрес сервера | все авторизованные пользователи |
| Версия | `appVersionLabel`, значение `local`, если версия не передана при сборке | все авторизованные пользователи |
| Выход | `DataProvider.logout()` | все авторизованные пользователи |

Непрерывной фоновой синхронизации и её журнала нет. Поэтому интерфейс говорит «Данные обновлены» и «Обновить», а не «Синхронизация включена». Время последнего успешного `fetchAllData()` показывается как вспомогательная информация; при ошибке нужно явно сообщить, что отображается кеш.

## Информационная архитектура

### 1. Состояние данных

Первый блок отвечает на два вопроса: насколько свежи данные и что можно сделать сейчас.

- Строка состояния: «Данные обновлены» и последнее известное время.
- Основное действие: «Обновить».
- На время запроса действие блокируется и показывает прогресс.
- После успеха время обновляется и появляется короткое подтверждение.
- После ошибки остаётся прежнее время и появляется сообщение: «Не удалось обновить. Показываем сохранённые данные» с повторным действием.

Windows-действия находятся рядом, но не смешиваются с обновлением:

- «Импортировать JSON» — выбрать выгрузку, затем владельца карт; доступно для `editor` и `admin`.
- «Запросить кешбэк» — выбрать профиль и запустить локальный Chrome-сценарий.
- На Android, iOS и web эти пункты не показываются как активные. В прототипе используется подпись «Windows», чтобы ограничение было понятно; production-вариант может скрывать их на неподдерживаемой платформе.

### 2. Управление данными

Блок видит только администратор. Он ведёт в существующие экраны:

- «Владельцы карт» — точнее текущей модели, чем «Семья» или «Участники»;
- «Карты»;
- «Банки»;
- «Правила MCC» с пояснением «Ревизии и публикация».

Числа справа — необязательные счётчики из уже загруженных списков. Они помогают оценить объём, но не должны задерживать открытие экрана. Для роли `editor` весь административный блок скрывается, а не показывается набором неработающих строк.

### 3. Параметры расчёта

«Расчётная дата кешбэка» — существующий инструмент просмотра данных на выбранную дату. Значение показывается прямо в строке. Если установлена не сегодняшняя дата, под ней появляется действие «Использовать сегодня» и заметный нейтральный маркер режима, чтобы пользователь не принял исторический срез за актуальный.

Это не общие «Настройки»: в приложении пока нет темы, языка, уведомлений или иных пользовательских параметров.

### 4. Аккаунт и приложение

Информационный блок показывает:

- логин и понятное название роли (`Администратор`, `Редактор`, `Просмотр`);
- сервер без токена и других секретов;
- версию приложения.

«Выйти» отделён от навигационных строк, окрашен семантически и требует отдельного нажатия. Подтверждение выхода не обязательно, поскольку операция не удаляет данные, но после нажатия должен быть немедленно понятен переход на экран входа.

### 5. Будущая семейная модель

Семейное пространство вынесено в отдельную ненажимаемую заметку «Позже». Оно не содержит кнопок «Пригласить», «Переключить семью» или настройки прав. Когда появятся домохозяйства, приглашения и роли внутри семьи, этот блок можно заменить полноценным разделом, не меняя остальную архитектуру «Ещё».

## Compact: телефон

- Один вертикальный поток с заголовком «Ещё».
- Карточка свежести данных идёт первой, затем сгруппированные строки.
- Нижняя навигация остаётся видимой; контент получает нижний отступ и не уходит под неё.
- Вся строка является целью нажатия не менее 48 dp; стрелка только подтверждает переход.
- Платформенное ограничение импортов передаётся текстом, а не только цветом.
- Служебные значения переносятся на вторую строку при крупном системном шрифте.

## Expanded: desktop и широкий планшет

- Основная навигация превращается в постоянную боковую панель; «Ещё» явно выделено.
- Контент ограничен читаемой шириной и разбит на две колонки: слева данные и параметры, справа управление и аккаунт.
- Блоки не растягиваются на всю ширину окна.
- При ширине ниже примерно 900 px колонки складываются в один поток; при ширине оболочки ниже tablet breakpoint применяется компактная навигация.
- Пункты списка доступны с клавиатуры, имеют видимый focus ring и не зависят от hover.

## Состояния и права

| Ситуация | Поведение |
| --- | --- |
| Загрузка обновления | индикатор в кнопке, повторный запуск заблокирован |
| Обновление успешно | новое время + краткое ненавязчивое подтверждение |
| Сервер недоступен | сохранённые данные остаются; сообщение объясняет состояние и предлагает повторить |
| Windows + admin | видны все блоки и оба сценария импорта |
| Windows + editor | видны импорт и запрос кешбэка, но нет административных справочников |
| viewer | только обновление, дата, сведения о сеансе и выход |
| Android/iOS/web | Windows-действия скрыты или явно недоступны с пояснением; макет не предлагает выбрать файл |
| Историческая дата | показана дата и действие «Использовать сегодня» |

## Визуальная и доступная подача

- Спокойный функциональный fintech: светлый фон, белые поверхности, тёмно-синий текст, синий интерактивный цвет, янтарный только для платформенных/временных оговорок, красный только для выхода.
- Иконки — единый контурный набор; emoji не используются.
- Основной и вторичный текст выдерживают контраст не ниже 4.5:1; границы и focus ring — не ниже 3:1 к соседней поверхности.
- Иконки рядом с видимым текстом декоративны для screen reader; standalone-кнопки получают доступное имя.
- `prefers-reduced-motion` отключает необязательные переходы; никакое состояние не зависит от анимации.
- Тёмная тема должна использовать семантические токены и проходить отдельную проверку перед реализацией. Макет фиксирует структуру, а не окончательную палитру приложения.

## Что сознательно не включено

- приглашение членов семьи, семейные роли и несколько семей;
- импорт операций и профиль наблюдений продавец → MCC;
- автоматическая синхронизация в фоне и журнал синхронизации;
- темы, язык, уведомления и другие отсутствующие настройки;
- активный «Автоимпорт MCC» как обещанная пользователю возможность: текущий endpoint остаётся заглушкой;
- изменение адреса сервера из «Ещё»: приложение показывает конфигурацию, но не предоставляет редактор адреса после входа.

## Решение для прототипа

PNG показывает один и тот же хаб в compact и expanded оболочках. Данные, имена и счётчики иллюстративны, а сами типы действий соответствуют текущему коду. Визуальная система продолжает направление существующих концептов CashFlow, но не считается утверждённой дизайн-системой.
