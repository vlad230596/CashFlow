## Границы модулей

- `backend/bank_identity.py`: стабильные интеграционные ключи банков и aliases; название и иконка остаются отдельными свойствами.
- `backend/cashback_validation.py`: единая валидация ручного создания/изменения категорий до изменения ORM-состояния.
- `backend/mcc_evaluation.py`: чистая оценка MCC, применяемая к отдельному запросу и офлайн-снимку.
- `backend/mcc_snapshot.py`: компактный транспорт снимка с общими правилами, без повторения условий для каждой карты.
- `backend/mcc_routes.py`: регистрация MCC Blueprint через зависимости без импорта глобального приложения.
- `app/lib/services/api_client.dart`: bearer-сессия, отбрасывание запоздалых ответов старой сессии, ошибки HTTP.
- `app/lib/services/reference_data_store.dart`: справочники за совместимым фасадом DataProvider.
- `app/lib/services/mcc_cache_store.dart`: сохранение и восстановление MCC-снимка; отдельный результат восстанавливается по запросу.
- `app/lib/services/import_coordinator.dart`: этапы импорта и явный результат частичного выполнения.
- `app/lib/services/business_clock.dart`, `app/lib/utils/cashback_period.dart`: московский календарь и пересечение периодов.
- `app/lib/services/monthly_plan_projection.dart`: группировка, сортировка, покрытие и дубли отдельно от дерева виджетов.
- `app/lib/services/card_context.dart`: представление карты с банком и владельцем.
- `app/lib/services/mcc_snapshot_analyzer.dart`: локальная диагностика/сравнение снимка вне файла экрана.
- `app/lib/utils/cashflow_formatters.dart`: форматирование процентов и календарных подписей.
- `app/browser_extension/adapters/cashback-amounts.ts`: общий парсер денежных условий категорий и акций.
- `contracts/cashback-amounts.v1.json`: синтетические общие примеры для Python и TypeScript.
- `app/browser_extension/adapters/selection-plan.ts`: проверка данных плана на границе bridge/storage и подпись выбранного периода.

## Офлайн MCC

Продолжение после исследования: [реализация от 2026-10-15](mcc-offline-implementation-2026-10-15.md)
заменяет описанный ниже первоначальный codec на schema 3, отдельное хранилище
и поиск из кэша с фоновым обновлением. Размеры и проверки ниже относятся к первому этапу.

Онлайн-обновление получает справочник и опубликованные правила для всего справочника через authenticated `GET /api/mcc/offline-snapshot?as_of=`. Поэтому после успешного сохранения можно искать также коды, которые ранее не запрашивались по отдельности. Поиск по названию использует сохранённый справочник. Детали MCC категории также восстанавливаются из снимка.

Кеш отделён по API-серверу, учётной записи и календарной дате. При отсутствии снимка нужного дня допустим последний сохранённый снимок этой же учётной записи/сервера: интерфейс показывает время получения и дату применимости правил. Ссылки на предложения старого дня исключаются, чтобы прежние условия не выдавались за текущую выгоду.

Снимок не копирует полный набор правил для каждой карты и каждого MCC. Он хранит общие payloads и ссылки, которые клиент раскрывает только для запрошенного результата. Повреждённый кеш игнорируется. Объём хранения ограничен.

Если обновлённый backend ещё не установлен, клиент сохраняет справочник и отдельно полученные результаты: проверка никогда не запрошенного MCC потребует полного снимка от новой версии API. Офлайн-режим не может узнать опубликованные после сохранения изменения банка.

## Согласованные контракты

- DELETE карты: 204; успешные изменения справочников обновляют локальное состояние и кеш.
- Обновление карты использует серверный ответ, включая лимит категорий и активность.
- Выбранный период плана передаётся в подтверждение и экспорт; `effectiveDate` сохранён, добавлен optional inclusive `period.from/to` в schemaVersion 1.
- Будущие акции загружаются вместе с остальными предложениями и фильтруются отдельно от уже действующих.
- Состояние выбора и подтверждение банком остаются разными фактами.
- Каноническая и приблизительная группировка сохраняют происхождение результата и разные стабильные ключи.
- Новая миграция `0011_bank_identity` добавляет `bank_key`; существующие aliases заполняются независимо от пользовательского выбора иконки.

## Дальнейшие архитектурные возможности

DataProvider сохраняется фасадом; оставшиеся доменные коллекции можно переносить по одной после текущих контрактных исправлений. Полное выделение всех ORM-моделей/Flask-маршрутов, смена state management и универсальный CRUD-framework не выполняются массовой заменой. Изменения контрактов и чистые доменные функции уже дают границы для следующих небольших изменений.

## Итоговая проверка

- Backend: 135 pytest-тестов и 8 subtests общих денежных примеров, без предупреждений; `ruff check .`, `uv lock --check`, генерация Alembic SQL успешны.
- Миграция 0011: изолированная SQLite, полный upgrade, downgrade до 0010 и повторный upgrade; backfill aliases проверен. Production/PostgreSQL migration не выполнялась.
- Flutter: полный suite — 142 теста; после последней защиты кеша дополнительно 11 targeted тестов; `flutter analyze` —No issues found.
- Flutter Web: release-сборка без внешнего CDN успешна; Wasm dry-run успешен.
- Расширение: TypeScript typecheck, 82 Vitest-теста, production WXT-сборка успешны.
- `git diff --check` успешен. Docker/integration CI и живые банковские кабинеты локально не проверялись.

Размер MCC-снимка измерен в изолированном synthetic-наборе: 1105 MCC, 6 банковских программ и 672 предложения. Это не инвентаризация production. Компактный schema 2 — 1 065 848 байт UTF8,809 383 кодовых единицы UTF-16 (примерно 1,62 МБ web-хранилища),2 088 154 байта JSON Flask на передаче. Сокращение 93,5%. Числовые коды сами по себе занимают небольшую долю объёма: размер создавали повторяющиеся названия, условия, исключения, сведения о программах и источниках.

Серверный preview реализован через `backend/mcc_preview.py`: read-only нормализация и полный diff. Создание черновика с preview-token отклоняет изменённый документ или базу сравнения. Отложенная публикация остаётся отдельным существующим действием; токен не переносится автоматически в последующие публикации.
