# Перенос парсинга на телефон — журнал исследования

Статус на 2026-09-25. Цель направления: перенести весь парсинг банков
(кэшбэк-категории, а в перспективе операции + MCC + лимиты по кредиткам) с
десктопного Chrome-расширения на телефон, чтобы обновлять данные без компьютера.

## Что выяснили

### 1. Как устроен текущий парсинг (Chrome-расширение)

Расширение `app/browser_extension/` (WXT/MV3), два механизма:

- **DOM-скрейпинг** — Sber, VTB, Yandex, Alfa, Ozon: content-скрипт читает
  отрендеренную страницу по устойчивым атрибутам (`data-qa-type` и т.п.).
- **Перехват/replay внутреннего API** — только T-Банк: скрипт в `world:MAIN`
  монки-патчит `fetch`/`XHR`, ловит ответ `/loyalty_api/api/bonuses`, при
  необходимости переигрывает POST с `credentials: 'include'`
  (`entrypoints/tbank-api-bridge.content.ts`).

Оба держатся на трёх столпах: (1) вручную авторизованная сессия в выделенном
профиле, (2) возможность инжектить JS в origin банка, (3) оркестрация через CDP
(`app/scripts/*.mjs`, `*.ps1`). Расширение не читает и не экспортирует cookie.

### 2. Как это делает ZenMoney (разбор APK `ru.zenmoney.androidsub_1093`)

- Нативное Android-приложение (Kotlin/Compose). Коннекторы банков —
  **JS-плагины (проект ZenPlugins)**, которые **скачиваются в рантайме** с сервера
  ZenMoney (`android.zenmoney.ru`, класс `PluginRemoteApi.fetchPlugin`), не зашиты
  в APK.
- Выполняются в **встроенном V8 (`libj2v8.so`)** в песочнице `ZenPluginSandbox` и
  **сами ходят в API банков напрямую по HTTPS/WebSocket** через нативный мост
  `app.zenmoney.plugin.network.{Fetch, Socket, WebSocket, CookieJar}`. Не WebView-
  скрейпинг, не серверная сторона.
- Логин: каждый плагин объявляет схему `preferences` (логин/пароль/OTP),
  приложение рисует нативную форму, значения уходят в JS-окружение плагина.
- Модель данных ZenMoney поддерживает MCC (`mcc INTEGER`), лимиты (`creditLimit`)
  и кэшбэк — но заполнение зависит от конкретного плагина/банка; кэшбэк идёт через
  отдельную подсистему распознавания.
- **Вывод:** механизм изначально портируется в headless/Node. Но готовых
  RU-розничных коннекторов под наши банки в публичном ZenPlugins нет (только
  `tinkoff-business`, `sberbank-by`, `alfabank-by`, `vtb-by`; Ozon и розничного
  T-Банка нет). Достать их можно лишь с приватного сервера ZenMoney — проприетарно
  и вне лицензии, не берём. Переиспользуем паттерн, не код.

### 3. Варианты архитектуры на телефоне (приложение — Flutter, все платформы)

- **A. In-app WebView (`flutter_inappwebview`).** Даёт сессию (логин руками),
  куки, инжект JS в страницу, перехват fetch/XHR. Портирует расширение почти 1:1;
  единственный путь для DOM-банков; логин ни одного банка воспроизводить не надо.
- **B. Headless HTTP на Dart (`http`/`dio` + `cookie_jar`).** Для API-коннекторов;
  гибрид: снять сессию из WebView, дальше тянуть headless. На Android можно в фон.
- **C. Встроенный JS-движок (`flutter_js`).** Только если нужен единый JS-коннектор
  headless; DOM-скрейперы тут не работают. Скорее избыточно.
- **Рекомендация — гибрид:** кэшбэк-категории через WebView-инжект (A), операции/
  API — через сессию из WebView + headless-вызовы (B). Рерайт допустим,
  поддержка коннекторов принимается.
- **Автоматизация:** «обновить по кнопке» — решаемо. Полный фоновый автосинк —
  Android с усилием, iOS практически нет.

### 4. Тест-стенд `experiments/bank_webview_probe/`

Отдельное Flutter-приложение (не связано с основным): 6 плиток-банков + адресная
строка, переключатель User-Agent (Desktop Chrome по умолчанию / Mobile / дефолт),
сброс кук, кнопка «в системный браузер», баннер ошибок, и **сетевой лог** (JS-хук
на fetch/XHR, только метаданные). Корни Минцифры вшиты как доверенные через
`android/app/src/main/res/xml/network_security_config.xml` (иначе Сбер/Альфа не
проходят TLS). Сборка: `C:\FlutterSdk\flutter\bin\flutter.bat`. Устройство: Galaxy
S23 по wifi adb.

Снятие лога: в приложении «Сохранить в файл» →
`/storage/emulated/0/Android/data/com.cashflow.bank_webview_probe/files/netlog.json`
→ `adb pull` (через PowerShell; Git Bash ломает путь `/storage/...`). Дубль в
logcat: `adb logcat -s flutter | grep NETLOG`.

### 5. Результаты живого прогона (2026-09-25)

- Пайплайн «WebView → перехват API → выгрузка файла → разбор» проверен: снято 163
  запроса. CSP банков перехвату не мешает.
- **Сертификат-фикс работает:** Сбер и Альфа открываются после вшитых корней
  Минцифры (TLS не обходится).
- **User-Agent Desktop** → банк отдаёт «компьютерный» веб-кабинет.
- **Ozon (был залогинен) — ключевой результат.** Кабинет дергает чистые
  JSON-API POST на сессии (`finance.ozon.ru/api/v4/*`), включая ровно то, чего нет
  у ZenMoney:
  - лимиты кредиток: `POST /api/v4/creditCard/limits`, `/api/v4/aggregatedLimits`,
    `/api/v4/creditProductsV5`, `/api/v4/creditCard/widgetV2`;
  - кэшбэк: `GET /apps/loyalty/_mf/info/MFFavoriteCategoriesV3`,
    `POST /apps/loyalty/api/loyalty/monthlyPromotions/getCurrent`,
    `POST /api/v4/loyalty/cashbackInfoV2`;
  - счета/баланс/карты: `/api/v2/activeProducts`, `/api/v4/cards/all`,
    `/api/v4/userBalance`.
  Это подтверждает реальность headless-подхода (C/B) для Ozon.
- **Антифрод/фингерпринт-хосты** в трафике: `back.vtb.fp.f6.security` (F6/Group-IB),
  `groupib-ac.alfaonline.org`, `visor.sberbank.ru`, `sage-collector.tbank.ru`,
  `mc.yandex.ru` — аргумент за гибрид (сессия из WebView), а не за голый
  реимплемент логина.

## Что ещё предстоит выяснить

- **Залогиненный проход по T-Банк, Сбер, Альфа, ВТБ, Яндекс:** зайти в кабинет,
  открыть раздел кэшбэка и историю операций, снять лог. Сейчас по ним поймана
  только страница входа/публичка.
- **T-Банк:** поймать `/loyalty_api/api/bonuses` под логином (подтвердить, что
  replay-подход переносится).
- **Ozon: история операций** — поймать фид транзакций (пока не открывали) и
  проверить наличие MCC.
- **MCC внутри ответов:** сейчас лог — только метаданные (метод/URL/статус). Чтобы
  увидеть MCC в теле операций, нужен аккуратный точечный захват тела только для
  нужного эндпоинта (чувствительные данные — делать осознанно).
- **Детект WebView по банкам:** проходит ли кабинет целиком во встроенном браузере
  под Desktop UA, не упирается ли в требование родного приложения.
- **Живучесть сессии / ре-логин / 2FA-канал:** насколько долго живёт авторизация,
  как организовать ввод OTP.
- **Решение по каждому банку:** чистый API (как Ozon) vs DOM/WebView; где и как
  доставать кэшбэк, операции, MCC, лимиты.
- **Стратегия фона по платформам** (Android foreground service vs iOS —
  по открытию приложения).
