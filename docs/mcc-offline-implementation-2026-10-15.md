# Офлайн MCC: реализация после исследования, 2026-10-15

Реализованы рекомендации из [исследования](research/mcc-offline-cache/analysis.md).
Данные и измерения ниже синтетические; production не изменялся.
Общий статус рефакторинга и открытые вопросы для следующего агента:
[refactoring-handoff.md](refactoring-handoff.md).

## Хранение и поиск

- `MccRepository` сразу возвращает локальный результат и обновляет его в фоне.
  Повторные запросы объединяются; интервал повторной проверки — одна минута.
- Полный снимок неизменяем. Ответы отдельных запросов хранятся отдельным слоем
  по дате, включая известные ответы 404. Один успешный запрос нового дня больше
  не удаляет вчерашний справочник и никогда не запрошенные MCC.
- Снимки изолированы по API URL, учётной записи и дате. Старые правила доступны,
  но прежние ссылки на предложения не используются для расчёта текущей выгоды.
  Интерфейс объясняет, когда выбор категорий требует обновления.
- В Web используется IndexedDB с транзакционной заменой записи. В native —
  файлы в application-support directory: сброс временного файла, переименование,
  сохранение предыдущего поколения для восстановления повреждённой записи.
  SharedPreferences остаётся источником миграции; старые данные удаляются только
  после успешной записи в новое хранилище.
- Ограничения: до трёх дат на scope и 32 MiB логических записей. Нативные резервные
  поколения и служебные данные имеют дополнительный физический размер. Очистка
  выполняется после успешной записи, последний полный снимок защищён.
- Ответы старого аккаунта/даты и запоздавшие сетевые ответы не заменяют новый
  контекст. Изменения привязок инвалидируют ETag и сохраняют dirty epoch через
  перезапуск; полный снимок и индивидуальные ответы согласуются версиями.

## Серверный формат

[Контракт schema 3](../backend/MCC_OFFLINE_CONTRACT.md) хранит нормализованные
ревизии, разреженный индекс решений по MCC с defaults и отдельные привязки
предложений. Банк по-прежнему оценивается на сервере; Dart только соединяет
сущности, без второго независимого алгоритма банковских правил.

`rules_version`, `bindings_version`, `content_version` разделены. Private ETag/304
проверяется до построения индекса и привязок. Неизменяемые правила кэшируются
сервером в ограниченном LRU. Для старых клиентов сохранён schema 2; новый клиент
также читает сохранённые schema 1/2.

На том же наборе 1105 MCC, 6 программ и 672 предложений: первоначальный развёрнутый
снимок — 16 484 366 байт UTF-8; schema 3 — 1 193 077 байт UTF-8 (около 1,19 MB),
сокращение около 92,8%. Это размер компактного JSON, не измерение сетевого трафика
или физической базы IndexedDB. Schema 2 был примерно на 12% меньше schema 3,
но использовал собственный универсальный codec; schema 3 упрощает контракт и
исключает построение развёрнутой матрицы. Холодное построение около 106,7 ms,
304 около 19,7 ms в локальном измерении. Путь 304 ещё читает поля для fingerprint;
это не постоянное время и не отдельный счётчик ревизии в БД.

## Проверка и границы

- Backend: 142 теста и 8 subtests; Ruff, lockfile, генерация Alembic SQL.
- Flutter: 167 тестов, включая настоящее файловое хранилище, повреждение/ошибку
  записи, смену дня и аккаунта, гонки ответов, dirty restart, обновление UI.
  `flutter analyze` без замечаний.
- Chrome: два реальных IndexedDB-теста — повторное открытие, изоляция ключей,
  rollback транзакции, полный снимок плюс ответ нового дня после перезапуска
  repository и отключения сети. Web release build без CDN и Wasm dry-run успешны.
- Общая синтетическая fixture проверяет совпадение серверного API и Dart reader;
  backend проверяет весь встроенный справочник из 1105 кодов и неизвестный 9999.

Для полного справочника требуется хотя бы один успешный снимок от обновлённого
API. Старый backend даёт лишь справочник и индивидуально сохранённые ответы.
В Web поиск работает без сети в загруженном приложении; данные IndexedDB
переживают перезапуск. Холодный запуск сайта без сети пока не обеспечен:
`web/cache_reset.js` удаляет service workers и CacheStorage оболочки приложения.
Отдельная PWA-политика в эти изменения не включена. Реальные банковские кабинеты
и production в этой проверке не использовались; изменения не развёрнуты.

При запуске browser-тестов Flutter SDK 3.41.8 на Windows обнаружена ошибка
маршрутизации CanvasKit: `flutter_web_platform.dart` преобразует URL в Windows
path, затем сравнивает его с `canvaskit/`, получая 404. Для проверки временно
скопированы ресурсы SDK `bin/cache/flutter_web_sdk/canvaskit` в `app/test/canvaskit`,
чтобы их отдал следующий static handler. После двух успешных тестов копия удалена;
SDK и приложение для этого обхода не изменены.
