# Многобанковский импорт кэшбэка: состояние MVP

Дата фиксации: 19 августа 2026 года.

## Пользовательский сценарий

1. В Windows-приложении CashFlow пользователь нажимает кнопку «Запросить кэшбэк».
2. Приложение запускает выделенный Chrome for Testing с профилем
   `.local/chrome-profiles/user-1`. Банковские cookie остаются только в этом профиле.
3. В расширение передаётся список банков. В первом MVP это все готовые интеграции:
   Т-Банк, Яндекс Пэй, Альфа-Банк, СберБанк, Ozon Банк и ВТБ.
4. Расширение открывает отсутствующие вкладки с целевыми страницами кэшбэка и
   показывает многобанковскую панель справа.
5. Банк, для которого обнаружена страница входа, выделяется красным. Пользователь
   самостоятельно проходит авторизацию; расширение не читает и не экспортирует cookie,
   пароли, номера карт, остатки и другие реквизиты.
6. При включённом «Автосборе» расширение раз в пять секунд повторно проверяет только ещё
   не готовые банки, не меняя их видимый статус на промежуточный и не прокручивая страницу.
   Также доступна кнопка «Собрать все».
7. Кнопка «Скачать JSON» сохраняет агрегированный файл в каталог `CashFlow` внутри
   пользовательских загрузок. Перед сохранением Chrome показывает стандартный диалог.

Сценарий остаётся read-only: парсеры могут открывать информационные панели банков,
чтобы получить условия, но не выбирают категории и не подтверждают банковские операции.

## Контракт JSON

Корневой объект содержит `schemaVersion`, время формирования, запрошенные банки и
массив всех запрошенных банков. Для каждого банка сохраняются:

- `bankId`, `bankName`, `collectionStatus`, `collectedAt`, `sourceUrl` в виде поля `url`
  и заголовок страницы;
- `authenticationStatus`;
- `selection.selectedCount` и `selection.visibleCount`;
- `selection.maxSelectable` и `selection.totalOptions`, если страница явно сообщает лимит;
- названия обнаруженных групп;
- все видимые категории, включая невыбранные, с процентом, статусом `selected`, иконкой,
  сроком, подзаголовком и полным текстом условий.
- `type: "standard"` для обычной категории или `type: "stackable_bonus"` для предложения,
  которое суммируется с основной категорией.

Если лимит или размер полного списка нельзя надёжно прочитать, поле равно `null`.
Количество видимых карточек не используется как догадка о максимуме выбора.

## Зафиксированные интеграции

### Т-Банк

- Целевая страница: `/mybank/bonuses/`. После закрытия и повторного открытия вкладки
  расширение работает непосредственно с обзорной страницей.
- Авторизация может выполняться на отдельном домене `id.tbank.ru`; он включён только для
  распознавания состояния входа.
- Основной источник — ответ штатного JSON-запроса страницы `loyalty_api/api/bonuses`.
  Он перехватывается в контексте авторизованной страницы, cookie наружу не передаются.
- Из группы месяца выбирается набор с активными категориями. Сохраняются все его варианты,
  `isActive`, процент, описание, MCC, URL иконки и базовый цвет. Максимум выбора считается
  как уже выбранные плюс оставшееся разрешённое количество из ответа банка.
- Это устранило зависимость от дочернего маршрута `/high-cashback/offer/{offerId}`: он
  иногда показывает только пустую оболочку. Расширение больше не
  прокручивает партнёрскую витрину и не принимает её предложения за месячные категории.
- Для «Все покупки» и «Развлечения» теперь используются прямые URL иконок из ответа банка;
  сохраняемый базовый цвет остаётся отдельным полем.

### Яндекс Пэй

- Основной источник: `https://sp.yandex.ru/cashback/current`.
- Выделенный Chrome запускается с русской локалью; интерфейс Яндекса зависит от языка
  браузера.
- Сохраняется отдельная подпись срока, например «ещё 43 дня».
- Текущая страница показывает активный набор; максимум выбора и полный исходный список
  могут отсутствовать, поэтому эти значения не выводятся предположением.

### СберБанк

- Страницы: `/app/loyalty/main/categories` и `/select` внутри SPA.
- После авторизации банк может оставить вкладку на `/app/main`; при автосборе расширение
  нажимает штатный элемент «СберСпасибо» в этой же вкладке. Прямой переход на вложенный
  URL не используется: без инициализации внутреннего роутера он сбрасывает сессию.
- Внутри «СберСпасибо» последовательно открываются только информационные элементы
  «Мои категории» → «Посмотреть» → «Выбрать». Checkbox и подтверждение не нажимаются.
- Количество вариантов и явный лимит извлекаются со страницы и не фиксируются в документации.
- Выбор определяется состоянием checkbox. При отсутствии checkbox поддерживается чтение
  статического списка уже выбранных категорий.

### Ozon Банк

- Страницы: `/lk/bonus` (сводка) и `/lk/cashback` (подробности).
- Парсер отделяет выбранные банковские категории от партнёрских предложений.
- Для каждой карточки открывается информационный bottom sheet и сохраняется полный текст
  условий. Срок действия сохраняется отдельно.
- Число выбранных карточек не считается доказательством общего максимума, поэтому
  `maxSelectable` остаётся `null`, если явного текста нет.

### ВТБ

- Страницы: `/bonus`, `/bonus/categories/months` и `/bonus/categories`.
- Количество доступных вариантов и лимит выбора извлекаются со страницы.
- Парсер последовательно открывает «Подробнее», получает MCC/лимиты и закрывает модальное
  окно. SVG-иконки сериализуются в data URL.
- Новая прямая вкладка иногда перенаправляется на вход, даже если старая вкладка активна;
  панель поэтому оценивает все вкладки банка и выбирает ответ с наиболее полным набором.

### Альфа-Банк

- Основной маршрут: `https://web.alfabank.ru/marketplace/?loyaltyType=104`.
- Обычные активные категории читаются из `data-test-id="chosen-category-item"`.
- Если информационная панель закрыта после повторного открытия страницы, расширение само
  открывает карточку «Категории в {месяце}» и забирает данные на следующем цикле автосбора.
- Подсказки читаются из `tooltip-category-info-target`, включая текст появляющегося tooltip.
- Промокатегория вне блока «Уже выбрано» сохраняется с `type: "stackable_bonus"`; обычные
  категории имеют `type: "standard"`. Правила суммирования описаны в
  `stackable-cashback.md`.
- Раздельные узлы процента и названия суммирующейся карточки объединяются в одну категорию;
  SVG `<image>` поддерживается наравне с обычным `<img>`.
- Сертификаты российской доверенной цепочки установлены только в локальное хранилище
  выделенного профиля Chrome; системное хранилище Windows не менялось.

## Технический pipeline

- Реестр банков и стартовые URL: `banks/registry.ts`.
- Банковская DOM-логика: `adapters/{bank}/cashback.ts`.
- Общий статус, метаданные выбора и контракт: `adapters/page-probe.ts` и `adapters/types.ts`.
- Многобанковский интерфейс: `entrypoints/sidepanel/`.
- Запуск из приложения: `lib/services/cashback_import_launcher_*` →
  `scripts/start_cashback_import.ps1` → DevTools-скрипт конфигурации.

Проверка и сборка:

```powershell
cd browser_extension
..\scripts\setup_node_env.ps1 -Run "npm run check"
cd ..
.\scripts\restart_cashflow_extension_chrome.ps1 -Profile user-1 -DebugPort 9223
```

Запуск полного сценария без Flutter:

```powershell
.\scripts\start_cashback_import.ps1 -Profile user-1 -DebugPort 9223
```

После изменения manifest/content scripts профиль лучше перезапустить: повторная загрузка
unpacked-расширения не всегда заменяет уже внедрённый content script в открытой SPA-вкладке.

## Границы первого MVP

- JSON пока скачивается пользователем и ещё не импортируется автоматически в backend.
- В JSON попадают все запрошенные банки. У неготового банка категории пусты, а причина
  фиксируется полями `collectionStatus`, `authenticationStatus` и `message`.
- Определение авторизации основано на URL, форме входа и факте получения категорий. Для
  нестандартной страницы без категорий статус может остаться «Ожидание», а не «Нужен вход».
- Общий regex читает только явно написанные русские формулировки лимита. Для банков с иной
  разметкой нужно добавить точечный адаптер метаданных.
- Автоматическое переключение месяцев, выбор категорий и подтверждение изменений не входят
  в read-only MVP.
