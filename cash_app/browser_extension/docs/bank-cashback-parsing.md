# Парсинг банковского кэшбэка

Документ описывает текущую реализацию расширения CashFlow Cashback Importer,
результаты интеграции с Т‑Банком и Яндекс Пэй, а также правила добавления
следующих банков.

## Цель

Расширение работает внутри отдельного авторизованного профиля Chromium и
преобразует страницу банковского кабинета в структурированный список категорий
кэшбэка. Пользователь авторизуется самостоятельно. Расширение не читает, не
копирует и не экспортирует cookie.

Текущий сценарий намеренно read-only: расширение читает страницу, но не
отмечает категории и не нажимает банковскую кнопку подтверждения.

## Формат результата

Категории всех банков представлены общим типом:

```ts
type CashbackCategory = {
  name: string;
  percent: number | null;
  percentLabel: string | null;
  subtitle: string | null;
  description: string | null;
  iconUrl: string | null;
  iconBackgroundColor: string | null;
  selected: boolean;
  group: string | null;
  expiresInLabel: string | null;
};
```

- `name` — название без процента.
- `percent` — числовое значение для последующей передачи в CashFlow.
- `percentLabel` — исходное представление процента.
- `subtitle` — дополнительная подпись карточки.
- `description` — полный текст подсказки со знаком вопроса. Здесь находятся
  лимиты, исключения, сроки начисления, условия подписок и ссылки на правила.
- `iconUrl` — URL исходной иконки банка.
- `iconBackgroundColor` — вычисленный цвет фона контейнера иконки.
- `selected` — категория уже выбрана либо отмечена пользователем на странице.
- `group` — смысловой раздел предложения на странице банка, например «Кешбэк
  при оплате онлайн и на кассе».
- `expiresInLabel` — исходная подпись оставшегося срока, например «ещё 43 дня»;
  сохраняется отдельно от общего описания.

Полный текст `description` сохраняется без попытки угадать смысл каждой суммы.
Например, сумма может быть максимальным бонусом, стоимостью подписки или
порогом покупки. Семантическое разбиение таких условий следует выполнять
отдельным нормализатором, не теряя исходный текст.

## Т‑Банк

### Маршруты

- Главная страница бонусов: `/mybank/bonuses/`.
- Страница конкретного набора категорий:
  `/mybank/bonuses/high-cashback/offer/{offerId}/`.

На главной странице присутствуют две разные карточки:

- категории, которые еще можно выбрать;
- уже активные категории текущего месяца.

Их нельзя смешивать: карточка выбора ведет к интерактивному списку, а карточка
текущего месяца — к статическому списку уже выбранных значений.

### Устойчивые DOM-признаки

Случайные CSS-классы Т‑Банка не используются. Парсер опирается на
`data-qa-type`, семантические атрибуты и отношения элементов:

- карточка категории: `[data-qa-type="category_item"]`;
- название: `[data-qa-type="category_title.line"]`;
- подзаголовок: `[data-qa-type="category_subtitle.line"]`;
- чекбокс выбора: `input[data-qa-type="category_checkbox.input"]`;
- значок вопроса: `[data-qa-type="category_tooltip-container"]`;
- контейнер иконки: `[data-qa-type="category_icon"]`;
- контейнер списка кэшбэка:
  `[data-qa-type="desktop-luca-cashback-select"]`.

Текст подсказки хранится в `aria-label` кнопки со знаком вопроса. Наводить мышь
для его получения не требуется. Это надежнее, чем читать временно созданный
popover после hover.

### Доступные и выбранные категории

На странице выбора каждая карточка содержит checkbox. Его `checked` определяет
поле `selected`.

На странице уже выбранных категорий checkbox отсутствует, а карточки находятся
в контейнере `desktop-luca-cashback-select` и имеют неинтерактивное состояние.
Такие карточки считаются выбранными (`selected: true`).

Оба варианта объединяются через `Set<HTMLElement>`, чтобы одна карточка не
попала в результат дважды.

### Проценты и названия

Строка вида `15% Страхование частных домов` разбивается на:

```text
percent = 15
percentLabel = "15%"
name = "Страхование частных домов"
```

Поддерживаются целые и дробные значения с точкой или запятой. Если формат не
распознан, название сохраняется целиком, а процент остается `null`.

### Иконки

Извлечения одного `img.src` недостаточно. Некоторые картинки Т‑Банка содержат
только белую плитку и черный символ, а цвет категории задается CSS-фоном
родительского контейнера. Это встретилось у категорий «Все покупки» и
«Развлечения».

Поэтому парсер сохраняет одновременно:

- `img.src`;
- `getComputedStyle(iconContainer).backgroundColor`.

Панель расширения восстанавливает и картинку, и цветной фон. Проверять нужно не
только наличие URL, но также `img.complete`, `naturalWidth` и фактический цвет
контейнера.

### Подсказки и важные условия

Поле `description` извлекается из `aria-label` значка вопроса. В проверенном
наборе таким способом были получены:

- исключения и ссылка на MCC для категории «Все покупки»;
- срок начисления кэшбэка за заказ в супермаркете;
- упоминание месячного лимита программы лояльности;
- перечень операций, относящихся к развлечениям;
- максимальные бонусы и условия подключения платных сервисов в доступных
  предложениях.

Текст показывается непосредственно в боковой панели, поэтому важное условие не
скрывается за hover и не теряется при импорте.

### Проверенный результат

Живая проверка подтвердила извлечение выбранных категорий, процентов, иконок,
цветов фона и полного текста подсказок. Конкретный набор аккаунта намеренно не
фиксируется в репозитории: категории и ставки являются пользовательскими и
меняются ежемесячно.

## Яндекс Пэй

### Локаль и маршрут

Кабинет доступен по `https://bank.yandex.ru/my`, а его краткая страница кешбэка
— по `/my/cashback`. Нажатие на блок текущей выгоды открывает полный список на
`https://sp.yandex.ru/cashback/current`. Именно полный список является основным
источником парсинга. Отдельного переключателя языка в настройках кабинета нет:
локаль берется из браузера. Поэтому выделенный профиль запускается с
`--lang=ru-RU` и `--accept-lang=ru-RU,ru,en-US,en`.

Перед разбором проверены одновременно `document.documentElement.lang = "ru"`,
`navigator.language = "ru-RU"` и параметр `l10n=ru` профильного iframe. Это
исключает смешение русских и английских названий в последующей нормализации.

### Выбранные категории месяца

Краткий блок «Выгода с Пэй в {месяце}» показывает только часть данных. Полная
страница содержит месячные категории, «Кешбэк дня» и активные предложения
уровня программы лояльности. Карточка определяется по префиксу
`SelectorListItem_block`, название — по `SelectorListItem_title`, процент — по
`PlusCashback_percent`, срок — по `SelectorListItem_endSlotLabel`, а важное
условие — по `SelectorListItem_subtitle`. Хешированный суффикс CSS Modules не
зашивается целиком.

Парсер использует `textContent`, а не `innerText`: в фоновой вкладке Chromium
может склеивать визуально разделенные строки `innerText`, из-за чего название и
процент перестают корректно разделяться. URL иконки берется из `currentSrc`/`src`.

Открытые ранее одинаковые вкладки могут восстанавливаться вместе с профилем,
причем часть из них остается со скелетоном без заполненных данных. Интерфейс
расширения опрашивает все подходящие вкладки и выбирает ответ с наибольшим
числом категорий. Дубли карточек удаляются по паре «название + процент».

На той же странице отдельно показаны кешбэк сервисов Яндекса, бонусы за остаток
и партнерские акции. Они не входят в месячный выбор и текущим адаптером намеренно
не смешиваются с ним.

### Проверенный результат

Живая проверка подтвердила извлечение названия, процента, группы, URL иконки,
оставшегося срока и дополнительного условия. Подписи срока и правила
суммирования сохраняются дословно из DOM, но конкретные значения аккаунта не
фиксируются в документации и не зашиваются в код.

## Альфа‑Банк

Следующий исследуемый кабинет — Альфа‑Онлайн по адресу
`https://web.alfabank.ru/`. Сервис использует российскую цепочку сертификатов.
Chrome for Testing без корневого сертификата Минцифры возвращал
`ERR_CERT_AUTHORITY_INVALID`; отключение проверки сертификатов не применяется.

Корневой `Russian Trusted Root CA` установлен через
`chrome://certificate-manager/localcerts/usercerts` в раздел «Установленные
вами → Доверенные сертификаты» только профиля
`.local/chrome-profiles/user-1`. Хранилища `CurrentUser` и `LocalMachine` в
Windows не изменены. Использован официальный пакет `gu-st.ru`; SHA-256
корневого сертификата:
`D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`.

Сервер Alfa отдаёт актуальный промежуточный `Russian Trusted Sub CA` 2024 сам,
поэтому отдельно он не устанавливался. Его SHA-256:
`2155785036C900DBB5F1BB2A1569C80C55595BD6BF94867A29BBDDBC7D88A3F2`.
После импорта обычный Chrome-профиль на DevTools-порту `9223` безопасно открыл
форму авторизации `private.auth.alfabank.ru`. Яндекс Браузер отложен и в
рабочем процессе не используется. После самостоятельной авторизации найден
маршрут `/marketplace/?loyaltyType=104` и панель категорий за текущий месяц.
Обычные выбранные категории находятся в элементах
`data-test-id="chosen-category-item"`; их пояснения открываются наведением на
`data-test-id="tooltip-category-info-target"`. Отдельная промокатегория,
показанная карточкой программы вне блока «Уже выбрано», должна сохраняться как
суммирующаяся. Её название, ставка и период всегда берутся со страницы.

Отдельное правило для предложений, которые начисляются поверх обычной выбранной
категории, описано в [stackable-cashback.md](stackable-cashback.md).

## СберБанк

Веб-кабинет работает на `https://online.sberbank.ru/`. Главный экран
СберСпасибо расположен на `/app/loyalty/main`, а нужные маршруты имеют вид:

- `/app/loyalty/main/categories` — уже подключённые категории;
- `/app/loyalty/main/categories/select` — доступные категории текущего месяца.

Раздел «Акции → Категории» на маршруте `/offers` является фильтром партнёрских
акций и не должен распознаваться как месячные категории кешбэка.

На экране выбора расширение извлекает все видимые варианты и состояние их
checkbox, но не нажимает кнопку подключения. Явная формулировка лимита читается
со страницы. После подтверждения выбора страница «Мои категории» должна отдавать
только активированные записи с `selected: true`.

Карточки выбора построены на обычных `input[type="checkbox"]`. Название и ставка
находятся в первой текстовой строке, пояснение — в следующей. Иконок категорий на
этом экране нет. Парсер не использует сгенерированные CSS-классы Сбера и отличает
категории по семантике чекбоксов и формату заголовка `N% Название`.

Конкретный набор, лимит и состояние выбора аккаунта не сохраняются в
репозитории; они входят только в сформированный пользователем JSON.

## Ozon Банк

Авторизованный кабинет находится на `https://finance.ozon.ru/lk`. Пункт «Выгода» ведёт на
`/lk/bonus`, а кнопка «Подробнее» в сводке кешбэка открывает маршрут `/lk/cashback`. Именно на
этом маршруте доступен полный блок выбранных категорий и их условий.

Парсер ограничивается контейнером `data-testid="categories-container"` и читает его элементы
`data-testid="carousel-item"`. Благодаря этой границе отдельный раздел «Выгода от партнёров» с
карточками «Кешбэк N%» и кнопками «Подключить» не смешивается с месячным выбором. Название и
процент имеют формат `N% Название`; иконка берётся из `img.currentSrc`/`src`, группа — из заголовка
«Категории в {месяце}», срок — из подписи «Копится до {дата}».

У каждой выбранной категории есть информационная кнопка. Во время чтения расширение по очереди
открывает эти справочные bottom sheet, сохраняет полный текст условий и закрывает их. Это только
операция чтения: расширение не нажимает «Можно выбрать снова», «Изменить» или «Подключить».

Живая проверка подтвердила чтение выбранных карточек, MCC, лимитов, исключений и
расчётного периода. Значения конкретного аккаунта не фиксируются в репозитории и
извлекаются из DOM при каждом запуске.

## ВТБ

Официальная веб-версия работает на `https://online.sbpvtb.ru/`. После авторизации раздел
«Выгода» открывается на `/bonus`, обзор месяцев — на `/bonus/categories/months`, а форма доступных
категорий — на `/bonus/categories`.

Расширение открывает форму просмотра, но не отмечает checkbox и не нажимает
финальную кнопку «Выбрать». Доступные варианты и лимит читаются со страницы;
состояние выбора берётся напрямую из `input.checked`.

Карточки определяются по `input[type="checkbox"][data-test-id^="checked_"]`. Название и процент
берутся из связанного `label[for]`, уровень — из заголовка перед
`.omega-ui-retail__checkbox-group`. Иконки ВТБ встроены в DOM как SVG, поэтому адаптер сериализует
их в локальный `data:image/svg+xml` URL. Для фоновых вкладок используется `textContent`, поскольку
`innerText` в Chromium может оказаться пустым.

Кнопка «Подробнее» каждой карточки открывается последовательно только для чтения. Из модального
окна сохраняются MCC, исключения и дополнительные условия, после чего окно закрывается. Лимит
кешбэка дополнительно читается из доступного `aria-label`, чтобы он не потерялся при изменении
визуальной разметки.

Карточки партнёров внутри формы являются вариантами месячного выбора, в отличие
от отдельного рекламного раздела с предложениями партнёров. Конкретный список
аккаунта и ставки в репозитории не сохраняются.

Особенность сессии ВТБ: новая вкладка может открыть `/login`, даже если исходная вкладка уже
авторизована. В цикле разработки поэтому обновляется существующая авторизованная вкладка, а не
создаётся новая.

## Архитектура расширения

- WXT + TypeScript + React.
- Manifest V3.
- Content script работает только на разрешенных доменах банка.
- Боковая панель запрашивает данные у content script через
  `browser.tabs.sendMessage`.
- Ответ обработчика сообщения возвращается как `Promise`. Синхронный возврат
  объекта в Chrome MV3 приводил к потере ответа.
- Банковская логика находится в `adapters/{bank}/`, а UI не должен знать детали
  конкретного DOM.

Т‑Банк разрешен через `https://www.tbank.ru/*`, Яндекс Пэй — через
`https://bank.yandex.ru/*` и `https://sp.yandex.ru/*`, Ozon Банк — через
`https://finance.ozon.ru/*`, ВТБ — через `https://online.sbpvtb.ru/*`. Для
каждого следующего банка нужно явно добавить минимальный `host_permission` и
отдельный content script.

## Профили и авторизация

Для двух пользователей применяются независимые директории:

```text
.local/chrome-profiles/user-1
.local/chrome-profiles/user-2
```

У каждого профиля свои cookie, local storage и банковские сессии. Профили и
локальные браузеры исключены из Git.

DevTools доступен только через `127.0.0.1`:

```text
user-1 -> port 9223
user-2 -> port 9224
```

## Особенности среды разработки

Обычный Google Chrome начиная с версии 137 игнорирует автоматический
`--load-extension`. Для разработки используется Chrome for Testing, установленный
в `.local/browsers/`.

Повторный `Extensions.loadUnpacked` с тем же ID не гарантирует замену уже
работающего content script. Надежный цикл обновления:

```powershell
cd browser_extension
..\scripts\setup_node_env.ps1 -Run "npm run check"
cd ..
.\scripts\restart_cashflow_extension_chrome.ps1 -Profile user-1 -DebugPort 9223
```

Перезапускается только выделенный профиль. Авторизованная сессия сохраняется.

## Ограничения текущей версии

- Переход к нужной карточке Т‑Банка пока выполняется вручную или через
  диагностический DevTools-сценарий.
- После SPA-перехода пользователь повторно нажимает кнопку чтения в панели.
- Данные еще не отправляются в backend CashFlow.
- Условия подсказки сохраняются полным текстом, но пока не нормализуются в
  отдельные поля наподобие `maxBonus`, `minimumPurchase` или `excludedMcc`.
- Автоматическое подтверждение выбора категорий намеренно не реализовано.

## Добавление следующего банка

Для каждого банка работа выполняется отдельно и в следующем порядке:

1. Добавить домен в минимальные `host_permissions`.
2. Создать отдельный авторизованный профиль или использовать согласованный
   существующий профиль.
3. Найти страницу доступных категорий и страницу уже выбранных категорий.
4. Зафиксировать маршруты и устойчивые DOM-признаки.
5. Проверить динамическую подгрузку, прокрутку, iframe и shadow DOM.
6. Извлечь название, процент, статус выбора, подзаголовок, полный текст условий,
   URL иконки и визуальные параметры контейнера.
7. Не использовать хешированные CSS-классы, если доступны `data-*`, ARIA,
   роли или семантическая структура.
8. Реализовать адаптер в `adapters/{bank}/` и отдельный content script.
9. Добавить тесты чистых функций нормализации.
10. Проверить адаптер на доступных и уже выбранных категориях живой страницы.
11. Убедиться, что чтение не вызывает выбор, оплату или подтверждение операции.
12. Запустить `npm run check`, перезапустить выделенный профиль и проверить
    результат в реальной боковой панели.

backend в него следует добавить поля `bank`, `sourceUrl` и при необходимости
`accountLabel`/`cardLabel` без хранения чувствительных реквизитов.
