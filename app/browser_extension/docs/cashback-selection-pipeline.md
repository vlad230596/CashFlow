# Целевой pipeline выбора категорий кэшбэка

## Цель

CashFlow должен пройти путь от пассивного просмотра банковских категорий до
управляемого двустороннего процесса:

1. Chrome extension собирает доступные и уже выбранные категории банков.
2. Приложение импортирует снимок и показывает его пользователю.
3. Пользователь меняет только те категории, выбор которых ещё не закреплён банком.
4. Приложение формирует JSON-план желаемого выбора.
5. Extension принимает план, открывает нужные банковские страницы и помогает
   применить изменения; в идеале — выполняет подтверждённые клики автоматически.
6. После применения extension создаёт новый снимок, который подтверждает
   фактическое состояние банков.

Фактический банковский снимок всегда важнее локального желаемого состояния.

## Текущее состояние

- Extension формирует входной JSON `schemaVersion: 1` по шести банкам.
- Сервер импортирует снимок идемпотентно по владельцу, банку, карте, категории
  и периоду.
- Приложение показывает выбранные категории, сроки и описания.
- Дополнительные категории с `type: stackable_bonus` не входят в обычный лимит.
- Срок выбора пока нельзя надёжно определить для каждого банка, поэтому
  `selection.isLocked` допускает `null`.

## Модель состояния категории

Состояние состоит из двух независимых признаков:

| `is_selected` | `is_selection_locked` | Значение |
| --- | --- | --- |
| `false` | `false` | Доступна для выбора |
| `true` | `false` | Выбрана локально, выбор ещё можно изменить |
| `false` | `true` | Не выбрана банком и уже недоступна |
| `true` | `true` | Выбрана и закреплена банком |

Заблокированные категории отображаются, но никогда не попадают в план
изменений. `stackable_bonus` может быть выбран и заблокирован, но не уменьшает
лимит обычных категорий.

## Входной снимок extension → приложение

Банковский блок должен содержать:

```json
{
  "bankId": "tbank",
  "selection": {
    "isLocked": true,
    "selectedCount": 4,
    "maxSelectable": 4
  },
  "categories": [
    {
      "type": "standard",
      "name": "Аптеки",
      "percent": 5,
      "selected": true,
      "description": "Полные условия категории",
      "maxCashbackAmount": 2000,
      "minPurchaseAmount": 5000,
      "expiresInLabel": null
    }
  ]
}
```

Пока адаптер не умеет доказательно определить блокировку, он передаёт
`isLocked: null`. Сервер временно применяет консервативную эвристику для старых
снимков: заполненный лимит или полностью активный набор считается закреплённым.
Эвристику нужно постепенно заменить явным банковским определением.

## Локальный выбор в приложении

- Изменять можно только `is_selection_locked == false`.
- Лимит считается только по обычным выбранным категориям.
- Приложение хранит отдельно фактический снимок и желаемый выбор. Нельзя
  перезаписывать фактическое состояние до подтверждения новым снимком банка.
- Перед экспортом приложение валидирует лимит, истёкшие сроки и отсутствие
  изменений в закреплённых категориях.

## Исходящий план приложение → extension

Первый формат плана:

```json
{
  "schemaVersion": 1,
  "kind": "cashback_selection_plan",
  "generatedAt": "2026-08-19T20:00:00Z",
  "sourceSnapshotGeneratedAt": "2026-08-19T18:16:34.746Z",
  "userId": 1,
  "banks": [
    {
      "bankId": "sber",
      "cardId": 1,
      "desiredCategories": [
        {"name": "Спорт и фитнес", "percent": 10}
      ]
    }
  ]
}
```

Имена подходят для MVP, но до автокликов желательно добавить стабильный
`sourceId`, извлечённый из банковского API или DOM. Процент и название тогда
останутся контрольными полями, а не идентификатором.

## Этапы применения плана в extension

### Этап 1 — подсказка

- Пользователь вручную загружает план в side panel.
- Extension открывает нужный банк.
- Желаемые категории подсвечиваются и выводятся чек-листом.
- Extension ничего не нажимает и не подтверждает.

### Этап 2 — подготовка кликов

- Extension сопоставляет категории со стабильными `sourceId` или проверенными
  DOM-селекторами.
- Показывает diff: что будет выбрано и снято.
- Может проставить чекбоксы, но финальное банковское подтверждение оставляет
  пользователю.

### Этап 3 — подтверждённая автоматизация

- Пользователь явно подтверждает план отдельно для каждого банка.
- Extension проверяет лимит и текущее состояние повторно непосредственно перед
  действием.
- После кликов сохраняет результат и собирает новый снимок.
- При расхождении прекращает работу по этому банку и показывает ошибку; никаких
  попыток «угадать» другой элемент.

## Защитные ограничения

- Никогда не менять закреплённые категории.
- Никогда не отправлять пароли, cookies и банковские токены в JSON-план или API.
- Не выполнять план, если исходный снимок устарел или страница показывает другой
  период.
- Не подтверждать необратимый банковский выбор без отдельного согласия
  пользователя.
- Записывать локальный журнал: банк, время, план, фактический результат и ошибку.

## Следующий большой checkpoint: авторизация и VDS

До публикации API во внешней сети необходимо:

1. Ввести пользователей сервера и безопасное хранение хэшей паролей.
2. Защитить все `/api/*`, кроме health/login, сессией или короткоживущим access
   token и refresh-механизмом.
3. Проверять владение каждой картой и категорией на сервере, а не доверять
   `user_id` клиента.
4. Включить HTTPS, ограниченный CORS, rate limiting и журнал входов/изменений.
5. Убрать жёсткий IP из Flutter и вынести адрес API в конфигурацию окружения.
6. Добавить миграции БД, резервное копирование и процедуру восстановления перед
   переносом на VDS.
7. Определить безопасный канал extension ↔ API; банковские cookies при этом
   остаются только внутри профиля Chrome.

Авторизация является блокирующим условием для размещения текущей базы и API в
публично доступной сети.

## Критерий готовности следующего функционального этапа

- Хотя бы один банковский адаптер надёжно определяет `isLocked`.
- Приложение хранит фактический снимок отдельно от желаемого плана.
- План экспортируется и импортируется side panel без ручного редактирования.
- Extension показывает точный diff и подсвечивает элементы хотя бы для одного
  банка.
- После ручного подтверждения новый снимок совпадает с желаемым состоянием.
