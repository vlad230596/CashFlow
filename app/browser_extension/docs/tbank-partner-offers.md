# Партнёрские акции Т-Банка: исследовательский сбор

Скрипт `app/scripts/collect_tbank_partner_offers.mjs` собирает доступные в
авторизованном профиле Chrome партнёрские предложения Т-Банка. Он читает страницы
`/mybank/bonuses/category/all/`, `/mybank/bonuses/categories/{category}/` и
`/mybank/bonuses/offers/{id}/`. Скрипт не добавляет акции в избранное и не
подключает их.

Запуск из `app/` после открытия Chrome с DevTools-портом 9223:

```powershell
& 'C:\Program Files\nodejs\node.exe' scripts\collect_tbank_partner_offers.mjs
```

Результат записывается в `.local/tbank-partner-offers.json`. Эта папка исключена
из Git: доступность предложений зависит от аккаунта и даты. Повторно прочитать
условия для уже собранного перечня можно через параметры
`9223 .local/tbank-partner-offers.json --details-only`. Скрипт сохраняет
промежуточный результат каждые 25 карточек. После повторного входа используйте
`--details-only --resume`, чтобы дочитать только карточки, для которых ещё нет
проверенных условий. Для проверки исключительно акций по чеку есть
`--details-only --receipt-only`.

Категории на странице являются разделами каталога партнёрских акций, а не
месячными категориями повышенного кэшбэка. Одно предложение может находиться в
нескольких разделах; связь хранится в `categories[].offerIds`. Скидки без
упоминания кэшбэка в заголовке сохраняются в `unclassifiedOffers` отдельно от
`offers`.

Список банка виртуализирован: обычный снимок DOM содержит только видимые
карточки. Скрипт прокручивает каждый раздел и сверяет число собранных карточек
с числом в интерфейсе банка. Идентификатор предложения пока извлекается из
React props карточки, поскольку он не опубликован в её HTML. Это делает
исследовательский скрипт зависимым от внутренней реализации сайта; при
переносе в расширение нужен устойчивый способ получить ID или переходить в
карточку штатным нажатием. Тексты правил сохраняются дословно. Числовая
нормализация ставок, лимитов и сроков должна выполняться отдельно, поскольку
формулировки различаются между акциями.

Есть два типа страниц условий: `STANDARD` с шагами получения и `RECEIPT` с
правилами покупки по чеку. У второго типа нужно сохранять условия товара,
способ оплаты, лимит, период и требование отсканировать QR-код чека.

Контрольный сбор 13 сентября 2026 года дал 24 раздела, 466 уникальных акций,
из них 436 с кэшбэком и 30 со скидкой. Из 436 карточек 380 имеют формат
`STANDARD`, 56 — `RECEIPT`. Число собранных карточек совпало со счётчиком банка
во всех разделах; у всех акций с кэшбэком удалось прочитать соответствующий
тип блока условий. Эти числа относятся к проверенному аккаунту и моменту сбора,
а не к постоянному каталогу банка.
