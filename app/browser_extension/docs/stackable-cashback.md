# Суммирующиеся категории кешбэка

## Зачем нужен отдельный тип

Некоторые предложения банка не заменяют обычную выбранную категорию, а
начисляются поверх неё. Такое предложение нельзя хранить как ещё одну обычную
категорию: при совпадении покупки должны примениться оба начисления.

В Alfa-Банке такое предложение показывается отдельной карточкой вне блока «Уже
выбрано». Парсер хранит его отдельно и помечает как суммирующееся; конкретные
название, ставка и период всегда извлекаются из текущей страницы.

Пример расчёта: если среди обычных категорий действует `5% Аптеки`, а отдельно
активна суммирующаяся категория `3% Аптеки`, ожидаемая ставка для подходящей
покупки равна `5% + 3% = 8%`. Каждое начисление при этом остаётся отдельной
записью со своими условиями и лимитами.

## Модель данных

Для такой записи требуется явная семантика суммирования. Рабочее название поля:

```json
{
  "name": "Пример категории",
  "cashbackPercent": 3,
  "type": "stackable_bonus",
  "stackingMode": "additive",
  "periodLabel": "в текущем периоде",
  "sourceBank": "Alfa-Банк"
}
```

Названия `type` и `stackingMode` пока считаются проектными: перед изменением
Flutter-модели и backend-контракта их нужно согласовать с окончательной схемой.

## Правило пайплайна

1. Парсер сохраняет обычные выбранные категории и суммирующиеся предложения
   раздельно.
2. Для каждой покупки сначала находятся все подходящие обычные категории.
3. Затем находятся подходящие записи с `stackingMode = additive`.
4. Итоговый процент складывается из применимой обычной ставки и всех применимых
   суммирующихся ставок.
5. Лимиты, минимальные суммы, способы оплаты, срок действия и исключения
   проверяются отдельно для каждого компонента. Проценты нельзя просто заранее
   объединить в одну категорию.

## Что ещё проверить

- Может ли одновременно действовать несколько суммирующихся предложений.
- Как банк применяет индивидуальные и общие месячные лимиты.
- Суммируется ли предложение с базовым кешбэком, партнёрскими акциями и
  повышенной категорией одновременно.
- Как отображать пользователю состав итоговой ставки, например `5% + 3%`.
- Какие признаки в DOM/API надёжно отличают суммирующееся предложение от
  обычной категории в других банках.
