# Подтверждение месячного кешбэка

Процесс состоит из трёх этапов: получение предложений, желаемый выбор в
CashFlow, проверка фактически сохранённого выбора в банке.

`is_selected` хранит желаемый выбор. `is_bank_confirmed` хранит доказательство
банковской активации. В активный кешбэк попадают только категории с обоими
признаками. Категории без подтверждения остаются в месячном выборе со статусом
«Ожидает подтверждения банка».

После сохранения выбора в банке нажмите «Проверить подтверждение в банках»
в расширении, экспортируйте новый JSON и импортируйте его в CashFlow.
Импорт обновляет данные приложения через существующий API.

Расширение передаёт `categories[].confirmed: true` только при доказательстве
активации из банка. Для Т-Банка это `isActive: true` в ответе API.
Для остальных банков подтверждение считывается из сохранённых банковских списков:
Альфа — `chosen-category-item`, Ozon — «Ваши категории» без элементов выбора,
Сбер — «Мои категории» на странице текущего месяца, ВТБ — карточки категорий
на `/bonus/categories/months` с выбранным текущим месяцем, Яндекс — список
на `/cashback/current`. Формы с галочками не подтверждают активацию.
Также принимается явно определённый адаптером `selection.isLocked: true`
вместе с `selected: true`. Заполненный лимит, все отмеченные категории и
галочки DOM сами по себе подтверждением не являются. Дополнительная категория
Альфы живёт на верхнем уровне в `cashback-programs-item`: подтверждение берётся
из карточки текущей месячной программы с сохранённой иконкой категории в footer
(`icon-view-group-item-wrapper`), без элементов выбора и кнопок активации.
Она сохраняет тип `stackable_bonus` и не расходует лимит обычных категорий.
Скидки с отрицательным процентом Яндекса не импортируются как кешбэк.

Свежий успешный импорт отзывает прежнее подтверждение отсутствующих или
неактивных категорий месяца, сохраняя желаемый выбор для повторной попытки.
Ошибки сбора и необходимость авторизации не подтверждают категории.

Перед запуском нового сервера выполните `uv run alembic upgrade head`.
Миграция `0004_bank_confirmation` оставляет старые записи неподтверждёнными:
для них нужен новый банковский снимок. Этот документ заменяет прежние
описания эвристического определения закреплённого выбора.
